# ccxt_to_tslab.py — инструкция

Скрипт скачивает свечи (OHLCV) с криптобиржи через библиотеку CCXT и сохраняет их в CSV-файл для офлайн-источника данных TSLab.

## Подготовка

Все команды запускаются из папки проекта (где лежат `ccxt_to_tslab.py` и `.venv`) в терминале VS Code. Используется Python из виртуального окружения `.venv`, в нём уже установлен `ccxt`.

```powershell
cd <путь к папке проекта>
```

## Куда сохраняются файлы

По умолчанию файлы сохраняются в папку `data` рядом со скриптом. Из какой папки запущен скрипт, значения не имеет. Имя файла формируется автоматически:

```
data/<биржа>_<пара>_<таймфрейм>.csv
```

| Параметры | Файл |
|---|---|
| `--symbol BTC/USDT` | `data/binance_btc_usdt_1m.csv` |
| `--symbol ETH/USDT --timeframe 1h` | `data/binance_eth_usdt_1h.csv` |
| `--exchange bybit --symbol BTC/USDT:USDT` | `data/bybit_btc_usdt_usdt_1m.csv` |
| `--timeframe 1M` (месяц) | `..._1mo.csv` (чтобы не путать с `1m`: Windows не различает регистр в именах файлов) |

Так у каждой комбинации биржи, пары и таймфрейма свой файл, и данные одной пары не попадут в файл другой. Путь можно переопределить через `--out` (конкретный файл) или `--data-dir` (другая папка).

## Основные сценарии

### 1. Обновить существующий файл (дозагрузка)

Если файл уже есть, скрипт находит в нём последнюю свечу и докачивает только новые, до последней закрытой свечи на текущий момент.

```powershell
.venv\Scripts\python ccxt_to_tslab.py --symbol BTC/USDT,ETH/USDT
```

Можно указать одну пару или несколько через запятую (подробнее в разделе «Несколько пар и таймфреймов за один запуск»).

Если новых свечей нет, скрипт выведет `Already up to date, nothing to fetch.` и ничего не изменит.

> **Важно:** если путь задан вручную через `--out`, `--symbol` и `--timeframe` должны соответствовать файлу. Таймфрейм скрипт проверяет по шагу свечей в файле, а пару проверить не может: в CSV нет информации о символе. При автоматическом имени файла эта ошибка невозможна.

### 2. Скачать новый файл

Для нового файла обязателен `--start`:

```powershell
.venv\Scripts\python ccxt_to_tslab.py --symbol SOL/USDT --start 2020-01-01
```

Потом этот файл можно обновлять командой из сценария 1.

### 3. Перекачать файл заново

`--full` игнорирует существующий файл и скачивает всё с `--start`:

```powershell
.venv\Scripts\python ccxt_to_tslab.py --symbol BTC/USDT --start 2020-01-01 --full
```

Загрузка идёт во временный файл `<имя>.tmp`, и старый файл заменяется только после успешного завершения. Если загрузка прервётся, прежние данные останутся целы.

### 4. Скачать ограниченный период

```powershell
.venv\Scripts\python ccxt_to_tslab.py --symbol BTC/USDT --timeframe 1h --start 2024-01-01 --end 2025-01-01
```

### 5. Несколько пар и таймфреймов за один запуск

В `--symbol` и `--timeframe` можно перечислить значения через запятую. Скрипт обработает все сочетания пар и таймфреймов, у каждого сочетания свой файл. Для каждого файла отдельно определяется, дозагружать его или скачивать с нуля:

```powershell
.venv\Scripts\python ccxt_to_tslab.py --symbol BTC/USDT,ETH/USDT,SOL/USDT --start 2020-01-01
.venv\Scripts\python ccxt_to_tslab.py --symbol BTC/USDT,ETH/USDT --timeframe 1m,1h,1d --start 2020-01-01
```

В первом примере BTC и ETH дозагрузятся (`--start` для них игнорируется), а для SOL будет скачан новый файл с 2020 года. Во втором получится шесть файлов: `binance_btc_usdt_1m.csv`, `binance_btc_usdt_1h.csv`, … `binance_eth_usdt_1d.csv`.

- Таймфреймы и символы проверяются до начала загрузки. Неподдерживаемый таймфрейм (например, `7m`) сразу остановит скрипт, а опечатка в символе (`FOO/USDT`) будет отмечена как ошибка только для этого символа.
- Если по одному сочетанию возникла ошибка (нет такого рынка, сбой сети, не тот файл), скрипт сообщает о ней и переходит к следующему.
- У всех файлов одинаковый конец периода, поэтому обновлённые вместе файлы заканчиваются на одной и той же свече.
- В конце выводится сводка:

```
Summary:
  BTC/USDT  1m  warning         +1086  binance_btc_usdt_1m.csv  1 gaps, 354 bars missing
  BTC/USDT  1h  ok                +19  binance_btc_usdt_1h.csv
  FOO/USDT  1m  FAILED              -  binance_foo_usdt_1m.csv  no such market on binance
```

Статусы в сводке:
- `ok`: всё скачано без пропусков;
- `up to date`: новых свечей нет;
- `warning`: скачано, но в данных есть пропуски или данные закончились раньше срока (подробности в конце строки);
- `gaps`: только в режиме `--check-gaps`, в файле найдены пропуски;
- `FAILED`: ошибка. Файл не менялся или дописан частично, следующий запуск продолжит с места остановки.

Если хотя бы одно сочетание завершилось с `FAILED`, код возврата скрипта равен 1.

`--out` можно использовать только с одной парой и одним таймфреймом.

### 6. Проверить пропуски в уже скачанных файлах

`--check-gaps` ничего не скачивает и не изменяет, а только читает файлы целиком и перечисляет пропущенные бары:

```powershell
.venv\Scripts\python ccxt_to_tslab.py --symbol BTC/USDT,ETH/USDT --check-gaps
```

```
Checking ...\data\binance_btc_usdt_1m.csv ...
  3545402 rows, 2020-01-01T00:00 -> 2026-09-29T17:08 (UTC)
  15 gaps, 2347 bars missing:
    2020-02-09T02:00 -> 2020-02-09T02:59      60 bars missing
    2020-02-19T11:36 -> 2020-02-19T17:29     354 bars missing
    ...
```

Для каждого пропуска указаны первый и последний отсутствующий бар (UTC, включительно) и число пропущенных баров. Файл на 3,5 млн строк проверяется примерно за 2 секунды. Заодно проверяется, что в файле нет пустых строк, битых строк и нарушений порядка по времени; если что-то найдено, сообщается номер строки.

Пропуски в минутных данных Binance с 2020 года — это технические работы биржи. Биржа не отдаёт свечи за эти периоды, поэтому перекачка файла их не заполнит.

### 7. Другая биржа

Биржа выбирается параметром `--exchange` (по умолчанию `binance`). Подходит любой идентификатор биржи из ccxt, всего их больше сотни: `bybit`, `okx`, `bitget`, `kucoin`, `gateio` и т. д. Название биржи входит в имя файла, поэтому данные разных бирж не смешиваются:

```powershell
.venv\Scripts\python ccxt_to_tslab.py --exchange bybit --symbol BTC/USDT --start 2022-01-01
# -> data/bybit_btc_usdt_1m.csv
```

- **Спот и фьючерсы** различаются записью символа: `BTC/USDT` — спот, `BTC/USDT:USDT` — бессрочный фьючерс с расчётами в USDT (файл `..._btc_usdt_usdt_1m.csv`).
- **Глубина истории зависит от биржи.** Binance, Bybit и OKX отдают минутки за годы. Kraken отдаёт только последние 720 свечей (для `1m` это 12 часов), поэтому за более ранний период придёт `no closed candles`. Если данные начинаются позже `--start`, скрипт выведет `data starts at ...`.
- Если такого символа на бирже нет, для него будет ошибка `no such market`, а остальные символы скачаются.

## Пропуски при загрузке

При загрузке скрипт так же перечисляет пропуски в новых данных, в том числе на стыке со старыми данными файла:

```
WARNING: 1 gaps in the downloaded data (UTC):
    2020-02-19T11:36 -> 2020-02-19T17:29     354 bars missing
```

Дополнительно могут появиться такие сообщения:
- `Note: data starts at ...`: для нового файла данные начинаются позже `--start`. Обычно это просто дата листинга пары (например, SOL на Binance с 11.08.2020). Это не ошибка.
- `Note: no data after ...`: биржа перестала отдавать свечи раньше конца периода, например из-за делистинга пары.

Для месячного таймфрейма (`1M`) пропуски не ищутся: месяцы разной длины.

## Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--out` | автоматически | Путь к конкретному CSV-файлу, если автоматическое имя не подходит |
| `--data-dir` | `data` рядом со скриптом | Папка для файлов с автоматическим именем |
| `--symbol` | `BTC/USDT` | Торговая пара или несколько через запятую: `BTC/USDT,ETH/USDT` |
| `--timeframe` | `1m` | Таймфрейм или несколько через запятую: `1m`, `5m`, `15m`, `1h`, `4h`, `1d`, `1m,1h` и т. д. |
| `--exchange` | `binance` | Идентификатор биржи в ccxt (`bybit`, `okx`, …) |
| `--start` | — | Начало периода (UTC): `YYYY-MM-DD` или `YYYY-MM-DDTHH:MM`. Нужен для нового файла и с `--full`; при дозагрузке игнорируется |
| `--end` | текущее время | Конец периода (UTC, не включается) |
| `--full` | выкл. | Перекачать с `--start` и перезаписать файл |
| `--check-gaps` | выкл. | Ничего не скачивать, только проверить существующие файлы и показать пропуски |
| `--limit` | `1000` | Сколько свечей запрашивать за один запрос |
| `--max-retries` | `5` | Сколько раз повторять запрос при сетевой ошибке |

## Формат файла (TSLab)

```
09/18/2026;23:59;80900;80924;80880.93;80883.87;64.10128;
```

`ДАТА(MM/dd/yyyy);ВРЕМЯ(HH:mm);OPEN;HIGH;LOW;CLOSE;VOLUME;`

- без строки заголовка и без пустых строк (TSLab прекращает чтение на первой пустой строке);
- время в UTC;
- объём указан в базовой валюте (BTC, ETH), а не в USDT;
- текущая, ещё не закрытая свеча никогда не записывается.

## Сообщения скрипта

| Сообщение | Что значит |
|---|---|
| `Removed partial last line (N bytes)` | Прошлый запуск прервался посреди записи. Оборванная строка удалена, дозагрузка продолжилась с корректной точки |
| `WARNING: N gaps in the downloaded data` | В новых данных есть пропуски, ниже перечислены их даты. Обычно это технические работы биржи, но перед бэктестом стоит учесть |
| `Note: data starts at ...` | Данные начинаются позже `--start`; как правило, это дата листинга пары |
| `Note: no data after ...` | Биржа не отдала свечи после указанного времени, хотя период ещё не закончился |
| `bar spacing in the file ... doesn't match --timeframe` | Указанный таймфрейм не соответствует файлу. Файл не изменён |
| `--start is required ...` | Файла ещё нет (или указан `--full`), поэтому нужно задать `--start` |
| `has empty lines at the end` / `line N is empty` | В файле есть пустые строки. Их нужно удалить вручную, иначе TSLab не прочитает данные после них |
| `line N is not a TSLab CSV row` / `is not after the previous row` | `--check-gaps` нашёл битую строку или нарушение порядка по времени в строке N |
| `file not found` | `--check-gaps`: файла для этой пары и таймфрейма нет |
